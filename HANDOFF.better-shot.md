**Tried and rejected:**
- `uridecodebin expose-all-streams=false caps=video/x-raw` for the frame reader — the demuxer errored with not-linked; `filesrc ! qtdemux name=d d.video_0 ! decodebin` works for the MOV/MP4 packages.
- Reading a cairo surface's pixels after `surface.clone()` — "Can't get exclusive access"; the exporter owns one `ImageSurface` and drops the `Context` before `data()`.
- `propagate_natural_width` / `max_content_width` to stop the studio inspector from growing — wrapped labels report their unwrapped text as natural width; `max_width_chars(34)` on wrapped labels plus `min_content_width(280)` fixed it.
- Reading the timeline width from `gesture.widget()` in click handlers — unreliable; the stored `DrawingArea` is measured instead. Initial keyboard focus landed in a spin button, so the preview is focusable and grabs focus on open.
- Sending EOS to the pipeline alone for the fixture source — `imagefreeze` is not a source element, so EOS never reached it and `stop()` timed out leaving only the first fragment; the fixture branch also gets EOS on the queue after it.
- x264 with RGB input — negotiated High 4:4:4, which players reject; the pipeline forces `video/x-raw,format=I420` before the encoder.
- Letting the poster size the card — a portrait recording made a 480×640 card; the picture is an overlay on a fixed-size frame.
- Cursor metadata via `pipewiresrc` — GStreamer drops SPA cursor metadata; a pointer timeline needs the `pipewire` crate and comes with the Phase 6 compositor.
- tiny-skia renderer — no text shaping with system fonts; cairo + Pango instead.
- Automatic scroll-capture frames via portal polling — BetterShot's own window would be in the frames (Wayland can't exclude it) and there are no global scroll events; the session uses explicit Add Frame.
- Mean-difference scroll registration — a static header outvoted moving content; shifts are scored by the share of matching textured rows.
- Streaming uploads through ureq readers — unsized bodies go out chunked, which R2 may reject; each object is sent as a sized buffer (progress advances per object).
- Synthetic `xdotool key alt+F4` and fast `xdotool click` — bypass the WM / too fast for GTK; scripts click the header close button and use mousedown/sleep/mouseup.
- `xdotool search --name` for titles containing ’ or — — never matches here; `check-ui.sh` has `window_titled` which compares names in bash.
- `pkill -f <pattern>` from an interactive shell — kills the shell when its own command line contains the pattern; use `pkill -x` or anchored patterns like `"^python3 .*fake-r2[.]py"`.

## Key Decisions
- **Decision:** Rust + GTK 4 (gtk4-rs 0.11, feature v4_14) + libadwaita 0.9 (v1_5), MSRV 1.92, targeting GTK 4.14 / libadwaita 1.5 (Ubuntu 24.04) · **Why:** native on GNOME; ashpd 0.13 needs gtk4 0.11 · **Alternative considered:** Qt/C++, Python+GTK.
- **Decision:** Region, OCR, color, and scrolling selection use a frozen full-desktop frame from the Screenshot portal · **Why:** Wayland can't show a live overlay over other apps.
- **Decision:** Global shortcuts map ⌘ → Super (Super+Shift+4 …), editor ⌘ → Ctrl; keys stored as GDK names · **Why:** macOS muscle memory; portal-friendly · **Alternative considered:** Print-key defaults.
- **Decision:** Files shared with macOS keep Swift `Codable` shapes (`{"case":{"_0":…}}`, reference-date doubles, uppercase UUIDs, `shareURL`, `bs_*` preference keys) · **Why:** one library/settings format across apps.
- **Decision:** OCR via the `tesseract` CLI (TSV word boxes) · **Why:** no build-time C deps; boxes drive smart redaction · **Alternative considered:** leptess/tesseract-rs.
- **Decision:** `oo7` keyring + `ureq` (rustls, platform verifier) for R2 · **Why:** oo7 shares ashpd 0.13/zbus 5 and covers Flatpak's Secret portal; ureq is small and runs on a worker thread · **Alternative considered:** hand-rolled Secret Service, libsoup.
- **Decision:** One Linux library (`HistoryStore`); share links live on `CaptureRecord.shareURL` · **Why:** macOS key compatibility · **Alternative considered:** a second store like macOS's `ScreenshotHistoryStore`.
- **Decision:** Linux changelog at `linux/CHANGELOG.md`; launch shows notes only for a release entry matching `version.json`, About shows `[Unreleased]` until then · **Why:** user decision; macOS notes described features Linux lacks.
- **Decision:** On X11 the recorder hides the cursor and samples it with `x11rb` (`pointerSynthesized: true`); on Wayland recordings embed the cursor and write an empty `input.json` (`pointerSynthesized: false`) · **Why:** `pipewiresrc` drops cursor metadata, a raw PipeWire consumer needs `unsafe` for SPA metadata (forbidden workspace-wide), and Wayland has no global pointer · **Alternative considered:** `pipewire` crate with a per-crate lint override.
- **Decision:** One capture bar window that morphs between the picker (64 px) and recording (38 px) rows, confirmations in `gtk::AlertDialog` · **Why:** AGENTS.md's shared bar and BarMetrics; a sheet on a tiny bar is unusable · **Alternative considered:** separate windows, `adw::AlertDialog`.
- **Decision:** Fragmented QuickTime (`qtmux fragment-duration=1000 fragment-mode=first-moov-then-finalise`), pause = PAUSED state · **Why:** crash-safe like the macOS writer; PAUSED keeps running time continuous so the movie has no gap.
- **Decision:** The studio keeps `edit.json` format 8 with Foundation's encoding quirks (whole doubles as integers, `[x, y]` points, legacy trim envelope) and keeps unedited fields verbatim · **Why:** projects must open on both platforms; a test rewrites a macOS project byte for byte.
- **Decision:** cairo compositor shared by preview and export; the preview is frame-stepped with a separate GStreamer `AudioPlayer` seeked per clip at the clip's speed · **Why:** one drawing path, no GPU dependency yet · **Alternative considered:** `gtk::MediaStream`/`playbin` preview (would not show the composited result).
- **Decision:** The output canvas is the cropped source size (`croppedVideoSize`), and the exporter averages viewport samples for motion blur while the preview samples once · **Why:** macOS behavior; blur costs little on export and would slow the preview.
- **Decision:** `BSD-3-Clause AND GPL-3.0-only AND AGPL-3.0-only` for core and app (Cap's zoom planning), with `Cap.txt` installed · **Why:** the plan's attribution rule for adapted Cap code.
- **Decision:** `BSD-3-Clause AND GPL-3.0-only` for core and app · **Why:** user decision; MacShot-derived scroll stitching.
- **Decision:** Work stays on `claude/wizardly-bohr-k43wf8` (AGENTS.md says maintainer work goes to `main`) · **Why:** the session's designated branch; the user hasn't asked to merge.

## Context for the next tool (3-5 sentences)
This repository is BetterShot, a macOS SwiftUI/AppKit screenshot app (`Sources/`, rules in `AGENTS.md`/`CONTRIBUTING.md`), being ported to Linux in a separate Rust workspace under `linux/` without changing the Swift code; each Rust module names the Swift file it ports, and shared formats (history.json with `shareURL`, `.bettershot` sidecars, share manifests, `bs_*` preference keys) stay compatible with macOS. The crates are `bettershot-core` (GUI-free logic and most tests), `bettershot-render` (cairo/Pango drawing shared by preview and export), `bettershot-platform` (ashpd portals, ksni tray, ureq R2 client, oo7 keyring), and `bettershot-app` (the GTK binary `bettershot`, single instance, CLI forwarded to it). Screenshots, the editor, OCR, color picking, smart redaction, pins, scrolling capture, R2 sharing, the Media Gallery, onboarding, What's New (from `linux/CHANGELOG.md`), screen recording (ScreenCast portal → GStreamer into the macOS `.bettershotrec` package, with the shared capture bar and recording cards), and the video studio (format 8 projects, clip cuts and speed, zoom springs, backgrounds, camera layouts, crop and masks, a shared cairo compositor, and GStreamer export) are done; 3D shots, teleprompter, subtitles, and packaging (Phase 7) remain, along with the studio follow-ups listed under Next Steps. Every UI change is verified with `linux/scripts/check-ui.sh` in light and dark, and user-facing Linux changes go under `## [Unreleased]` in `linux/CHANGELOG.md`. Claude Code wrote this handoff; any tool on any machine can resume from the steps under Working Environment.
